# 验收规格（ACCEPTANCE）

> English: [ACCEPTANCE.en.md](ACCEPTANCE.en.md)

> 这份文档只讲一件事：**怎么证明一个插件"真的能跑"**。
> 它是拿一次真实事故换来的 —— 那次的形态是：**语法检查全过、模块级自测全过，却因为一个未定义的常量，让 7 个入口全部崩在同一行，服务停摆了十几个小时。**

## 一、七个插件共用五条

| 判据 | 做法 | 不合格的样子 |
|---|---|---|
| **甲 加载级** | `import()` 真的加载它 + 用桩上下文调 `apply()` | 语法过、单测过，一加载就 `ReferenceError` |
| **乙 零副作用** | 用临时根跑；真邮局的 `mtime` 一动不动；不发真信 | 自测跑完，真数据被改了 |
| **丙 机器可判** | **只看退出码**（0 过 / 非 0 不过） | 靠"文案里有没有某句话"判断成败 |
| **丁 无凭据** | 全部文件扫描：密钥、凭据、口令 **0 命中** | "只是本地用的"密钥被提交进去 |
| **戊 接口可替换** | 换成假 provider ⇒ 核心行为不变；核心文件里 grep **任何成员名 / 真实类型标识 / 内网路径** ⇒ **0 命中** | 核心认字，一换名单就崩 |

> **戊 是"不会泄露"的硬证明**：核心不认识任何名字与类型，泄露就无处可泄。

## 二、逐件判据

| 件 | 至少要有这些 |
|---|---|
| `bus` | 验签往返；改一个字节必不过（**投递模式 `mode` 也要进签名**）；幂等（同一封信只消费一次）；落盘原子；握手闸 |
| `roster` | 只吃 provider 的数据；成员名 0 命中；组名单会排除发件人自己；坏输入不抛未捕获异常 |
| `types` | 注册／查询；未注册的类型**当场拒**且语义写进文档；**测试里新加一个类型，核心一行都不用动**；真实类型标识 0 命中 |
| `deliver` | 离线件真的留在信箱（不消费）；在线件当轮投出且**只投一次**；**收件人没有活体会话 ⇒ 信留在 `inbox`** |
| `gate` | 越额拒发 ＋ 退出码非 0 ＋ 不落信箱；组发按收件人数计单位；回环闸按"N 分钟 M 封／链深／纯回执"拦；空正文拒发 |
| `verify` | **默认禁用**时放行但带 `skipped: true`（★不假装验过）；开启后 fail-closed（缺字段／**未登记字段**／摘要不符／签名不符／白名单外 ⇒ 一律不过）；★**冒名必不过**（拿别人的钥匙签我的名字）；提示：未开启第 1～3 天每天至多印一次、**第 4 天起不再印**，而 `status().enabled` **永远是真相** |
| `cli` | 零依赖；参数顺序无关；错值拒发；帮助文本里没有内部信息 |

## 三、三条硬规矩

1. **不看中文，只看退出码。**
2. **能原地重复跑**：连跑两次，结果一致。
3. **负向测试**：**故意改坏一行 ⇒ 自测必须变红。**
   不红的自测等于摆设 —— 它只证明了"代码没崩"，没有证明"它真的在检查"。

## 四、完工判据

> **加载级自测 ＋ 真启一遍、看日志无加载错。**

**光比哈希、光跑模块级自测，都不算。**
哈希只证明"文件没变"，模块自测只证明"这个模块自己没崩" —— 都没证明**它挂进引擎以后能活**。

> ★★ **而且 `--dump-config` 也不算** ✗ —— **2026-10-10 我们自己栽的实证**：
> 六件全部通过"加载级自测"，`dsh plugin --profile <一次性> add link:…` 全部退出码 0，
> `--dump-config` 里**六层整整齐齐全在组合树里** ✓ —— ★**看着完美** ✓。
> 然后**真启一遍**：★**六件全部 `failed to apply`** ✗，原因是
> `cannot get property "whale" without inject`（`apply()` 里读了 `ctx.whale` 属性；
> 真 Cordis 里读它要先 `inject`）。
> ⇒ ★**`--dump-config` 只组配置树、根本不跑 `apply()`** —— 它连"插件能不能 apply"都证明不了 ✗。
> ⇒ 判据只有一条：**真启一遍，看日志里没有加载错** ✓。
> （★这一步现在也钉成了静态判据：源码里不许出现 `ctx.whale =` 或 `ctx?.whale?.` ⇒ 0 命中。）

## 五、怎么跑

```bash
node packages/cli/index.js selftest   # 退出码 0 = 过；非 0 = 不过
```

自测在**临时目录**里造一个假邮局，**绝不碰真数据**。

## 六、边界与限制（写清楚，免得下一个人当成保证）

* ★**核心信任两个接口 provider（`roster`／`types`）** —— ★**provider 撒谎，核心拦不住**：比如让未注册的类型 id 也 `resolve` 出来，类型检查就形同虚设。★这是**有意的设计选择**：核心**不认识任何类型标识**，所以它**没法自己判定"什么才算合法类型"**。⇒ 要防这一层，就在 **provider 那一层**加校验与自测。
* ★**链深闸不是安全边界**：它依赖回信人老实带 `re` —— 不带就重置。它是**礼貌闸／省米闸**。
* ★★**`verify` 禁用时什么都不拦** ✗ —— ★**它不等于"默认安全"**：默认那一档是"**已知不安全 ＋ 每天提醒你**"。要安全就写 `enabled: true`；装了这个件**不等于**打开了验签。
* ★**`--force` 会绕过回环闸三闸**：这是有意留的逃生门，但**留痕**（台账记 `forced`）。
* ★**只解决"同一台机器"**：信箱是盘上的目录；跨机器要靠共享目录。
* ★**没测到的**：多进程**并发抢同一封信**的行为（只做了代码走查）；`seen` 状态数组超长后的截断路径（只做了人工造件）。★这两条**别当成已保证**。
