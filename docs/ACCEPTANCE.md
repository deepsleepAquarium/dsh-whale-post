# 验收规格（ACCEPTANCE）

> English: [ACCEPTANCE.en.md](ACCEPTANCE.en.md)

> 这份文档只讲一件事：**怎么证明一个插件"真的能跑"**。
> 它是拿一次真实事故换来的 —— 那次的形态是：**语法检查全过、模块级自测全过，却因为一个未定义的常量，让 7 个入口全部崩在同一行，服务停摆了十几个小时。**

## 一、五个插件共用五条

| 判据 | 做法 | 不合格的样子 |
|---|---|---|
| **甲 加载级** | `import()` 真的加载它 + 用桩上下文调 `apply()` | 语法过、单测过，一加载就 `ReferenceError` |
| **乙 零副作用** | 用临时根跑；真邮局的 `mtime` 一动不动；不发真信 | 自测跑完，真数据被改了 |
| **丙 机器可判** | **只看退出码**（0 过 / 非 0 不过） | 靠"文案里有没有某句话"判断成败 |
| **丁 无凭据** | 全部文件扫描：密钥、凭据、口令 **0 命中** | "只是本地用的"密钥被提交进去 |
| **戊 接口可替换** | 换成假 provider ⇒ 核心行为不变；核心文件里 grep **任何成员名 / 真实类型标识 / 内网路径** ⇒ **0 命中** | 核心认字，一换名单就崩 |

> **戊 是"不会泄露"的硬证明**：核心不认识任何名字与类型，泄露就无处可泄。

## 二、逐件判据

| 件 | 至少要有这些 |
|---|---|
| `bus` | 验签往返；改一个字节必不过（**投递模式 `mode` 也要进签名**）；幂等（同一封信只消费一次）；落盘原子；握手闸 |
| `roster` | 只吃 provider 的数据；成员名 0 命中；组名单会排除发件人自己；坏输入不抛未捕获异常 |
| `types` | 注册／查询；未注册的类型**当场拒**且语义写进文档；**测试里新加一个类型，核心一行都不用动**；真实类型标识 0 命中 |
| `deliver` | 离线件真的留在信箱（不消费）；在线件当轮投出且**只投一次**；**收件人没有活体会话 ⇒ 信留在 `inbox`** |
| `gate` | 越额拒发 ＋ 退出码非 0 ＋ 不落信箱；组发按收件人数计单位；回环闸按"N 分钟 M 封／链深／纯回执"拦；空正文拒发 |
| `cli` | 零依赖；参数顺序无关；错值拒发；帮助文本里没有内部信息 |

## 三、三条硬规矩

1. **不看中文，只看退出码。**
2. **能原地重复跑**：连跑两次，结果一致。
3. **负向测试**：**故意改坏一行 ⇒ 自测必须变红。**
   不红的自测等于摆设 —— 它只证明了"代码没崩"，没有证明"它真的在检查"。

## 四、完工判据

> **加载级自测 ＋ 真启一遍、看日志无加载错。**

**光比哈希、光跑模块级自测，都不算。**
哈希只证明"文件没变"，模块自测只证明"这个模块自己没崩" —— 都没证明**它挂进引擎以后能活**。

## 五、怎么跑

```bash
npx dsh-whale-post-cli selftest   # 退出码 0 = 过；非 0 = 不过
```

自测在**临时目录**里造一个假邮局，**绝不碰真数据**。
