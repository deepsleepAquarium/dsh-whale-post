# 邮局 · whale-post

> English: [README.en.md](README.en.md)

> ★**一句话**：**给同一台机器上的多个 AI 会话（或多台引擎）一个"异步信箱"** —— 信按文件落盘、默认**不叫醒**对方、**不会丢**、**不会刷屏**。

## 它解决什么问题
1. ★**会话之间不能互相说话**：一个引擎里跑着好几个会话（网页端一个、机器人端一个、还有按需起来的小助手），彼此看不见对方在说什么 ⇒ 邮局让它们**留信**。
2. ★**"叫人"很贵**：想通知对方就得**把对方的会话叫醒** ⇒ 对方要为这一句付一次**满上下文推理**（最贵的浪费）⇒ ★所以**默认离线**：信落进对方信箱，**等人自己来读**。
3. ★**来回对发停不下来**：两个 AI 客气起来能对发到天亮 ⇒ ★**回环闸**（同一对 N 分钟内限封数／链深限跳／纯回执拒发）＋**配额闸**（多发一封＝多烧一份钱）。

## 用了以后什么效果
* ★★**一句话原则**：★**离线＝主力；在线＝应急储备** —— ★离线配额**大**、**不占**其它桶、★**不会一下堆满对方的会话窗口**、★**离线用完了还有在线兜底**；★**在线要攒着**（★**在线的先打光，真急事就只能"咬牙掏钱"发加急** —— 越额按费率计费（费率可配置））。
* ★**信只会晚到，不会不到**：★**收件人没有活体会话 ⇒ "不投也不消费"** ⇒ 信原样留在信箱里，对方下次开工**一拉就全到**（★这条我们真靠它救过急）。
* ★**跨引擎**：谁跑在哪个引擎上、哪个模型上，都无所谓 —— 信箱是**盘上的目录**。
* ★**不刷屏，也不会没人看**：★**两档判据** —— **默认离线**；★**正在来回协作 ⇒ 在线优先**；★**非急件攒到 ≈3 封 ⇒ "离 3 在 1"**（≈**3 封离线 ∶ 1 封在线** —— ★那一封在线的用处是"**来收信**"的**铃**：★离线信箱**不会丢信**，但**会被忙人忘掉**）；★**出事／停摆／要对方当刻动手 ⇒ 一律在线、不受比例约束**。★详见 [`docs/FOR-AGENTS.md`](docs/FOR-AGENTS.md)。
* ★**省钱**：配额按"单位"算，越额就**当场拒发**并给出非零退出码 —— ★**不悄悄降级**。
* ★**换得掉**：名单、类型表、投递策略、闸，**全是插件接口** ⇒ 你可以只换掉其中一件（比如把名单从 JSON 换成数据库）。

## 快速开始

> ★**已发 npm** ⇒ 直接用 `npx dsh-whale-post-cli …`（或先 `npm i -D dsh-whale-post-cli`）；想在仓内开发，用 `node packages/cli/index.js …` 也一样。
```bash
dsh plugin --profile <profile> add link:/abs/path/to/dsh-whale-post # 或用 registry 名
npm install                          # ★仓内要先装一次（把五个插件链进 node_modules；否则 CLI 找不到兄弟件）
node packages/cli/index.js selftest  # ★看退出码
node packages/cli/index.js hello --as alice
node packages/cli/index.js hello --as bob   # ★先握手：没握过手不许发（协议如此）
node packages/cli/index.js send --as alice --to bob --subject 'hi' --body 'first letter'
node packages/cli/index.js pump --as bob    # bob 读信（读走即消费）

# 或者用 npm 上那一份（不用 clone、不用 npm install）：
npx -y dsh-whale-post-cli@0.1.1 selftest
```
★装法、接线、接口表、写插件规范 ⇒ 见 [`docs/INSTALL.md`](docs/INSTALL.md)；★**给 AI 体看的用法纪律** ⇒ 见 [`docs/FOR-AGENTS.md`](docs/FOR-AGENTS.md)。

## 现状

* `packages/` 里**六件已落地**：`bus`（核心：信封／签名／握手／幂等／落盘）／`roster`（名单接口）／`types`（类型注册表接口）／`deliver`（投递策略）／`gate`（配额与计费闸 ＋ 回环闸）／`cli`（零依赖命令行）；`example/` 是一份"**怎么把它们接起来**"的组合示例。
* **一把跑完自测**：`node scripts/selftest-all.mjs` —— **退出码 0 ＝ 六件全过**（条数由它自己打出来，不在本文件里写死）。
* 每件都过三关：**能加载 ＋ 能跑 ＋ 跑错会红**（验收规格见 [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md)）。
* 版本 `0.1.0`（打了 tag **`v0.1.0`**，要引用就钉它）；接口带 `apiVersion`，**类型可以随时扩充**（加类型不用动核心）。
* **装法已在真引擎上实测过一遍**：五件按 `dsh plugin --profile <p> add link:<本仓>/packages/<件>` 装进一个**一次性 profile** ⇒ 它们**出现在 profile 配置树里**（`dsh --profile <p> --dump-config` 能看到 `dsh-whale-post-*` 五行）⇒ **真启一遍成功、对外服务正常、日志无加载错** ⇒ 用完把那个 profile 删掉，**在役的两台引擎全程没重启**。
  ★踩到的坑写在这儿免得别人再踩：插件包**必须**声明
  ```json
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
  ```
  少了这一行，`dsh plugin add` **只会把它当普通依赖装进去、不会激活成 profile 层** ✗（我们第一版就漏了，靠这次实测抓出来）。

## 它不是什么
* **不是聊天室**：没有实时推送、没有已读回执焦虑（**异步信箱**）。
* **不是 RPC**：不保证对方立刻处理（保证的是**信不丢**）。
* **不是分布式队列**：它假设**同一台机器**（同一份盘）；跨机器要靠共享目录。

## 三条设计取舍（★都写明了为什么）
| 取舍 | 为什么 |
|---|---|
| ★**默认离线** | 叫醒对方＝让对方付一次满上下文推理；默认省下它 |
| ★**只投活体，不活就"不投也不消费"** | 怕丢信 ⇒ 宁可信晚到（信留信箱，人来了再给） |
| ★**拒发就是拒发（不静默降级）** | 悄悄降级＝让人以为发出去了 ⇒ 最危险（我们踩过"急件写成 `ONLINE` 就永远叫不醒人"） |
