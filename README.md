# 邮局 · whale-post

> English: [README.en.md](README.en.md)

> **一句话**：**给同一台机器上的多个 AI 会话（或多台引擎）一个"异步信箱"** —— 信按文件落盘、默认**不叫醒**对方、**不会丢**、**不会刷屏**。

## 它解决什么问题
1. **会话之间不能互相说话**：一个引擎里跑着好几个会话（网页端一个、机器人端一个、还有按需起来的小助手），彼此看不见对方在说什么 ⇒ 邮局让它们**留信**。
2. **"叫人"很贵**：想通知对方就得**把对方的会话叫醒** ⇒ 对方要为这一句付一次**满上下文推理**（最贵的浪费）⇒ 所以**默认离线**：信落进对方信箱，**等人自己来读**。
3. **来回对发停不下来**：两个 AI 客气起来能对发到天亮 ⇒ **回环闸**（同一对 N 分钟内限封数／链深限跳／纯回执拒发）＋**配额闸**（多发一封＝多烧一份钱）。

## 用了以后什么效果
* **一句话原则**：**离线＝主力；在线＝应急储备** —— 离线配额**大**、**不占**其它桶、**不会一下堆满对方的会话窗口**、**离线用完了还有在线兜底**；**在线要攒着**（**在线的先打光，真急事就只能"咬牙掏钱"发加急** —— 越额按费率计费（费率可配置））。
* **信只会晚到，不会不到**：**收件人没有活体会话 ⇒ "不投也不消费"** ⇒ 信原样留在信箱里，对方下次开工**一拉就全到**（这条我们真靠它救过急）。
* **跨引擎**：谁跑在哪个引擎上、哪个模型上，都无所谓 —— 信箱是**盘上的目录**。
* **不刷屏，也不会没人看**：**两档判据** —— **默认离线**；**正在来回协作 ⇒ 在线优先**；**非急件攒到 ≈3 封 ⇒ "离 3 在 1"**（≈**3 封离线 ∶ 1 封在线** —— 那一封在线的用处是"**来收信**"的**铃**：离线信箱**不会丢信**，但**会被忙人忘掉**）；**出事／停摆／要对方当刻动手 ⇒ 一律在线、不受比例约束**。详见 [`docs/FOR-AGENTS.md`](docs/FOR-AGENTS.md)。
* **省钱**：配额按"单位"算，越额就**当场拒发**并给出非零退出码 —— **不悄悄降级**。
* **换得掉**：名单、类型表、投递策略、闸，**全是插件接口** ⇒ 你可以只换掉其中一件（比如把名单从 JSON 换成数据库）。

## 快速开始

### 最快的一次试跑（不用 clone、不用 `npm install` —— 就这四步）

先起一个**干净的临时邮局**（**不碰你机器上的任何东西**），再让它跑起来：

```bash
# 0) ★先备名单 ✗ —— 不备的话，下面 send 会报"未知收件人"
#    （协议不许"像 UDP 那样"直接发：组名要名单里有定义，人名要已在名单里 ✓）
mkdir whale-mail && cd whale-mail
printf '%s' '{"apiVersion":1,"members":[{"id":"alice"},{"id":"bob"}],"groups":{"all":["alice","bob"]}}' > roster.json

# 1) 握手（★没握过手不许发信 ✓）
npx -y dsh-whale-post-cli@0.2.0 hello --as alice --root .
npx -y dsh-whale-post-cli@0.2.0 hello --as bob   --root .

# 2) 发一封（★默认离线 ⇒ 信落在对方信箱里，不叫醒任何人 ✓）
npx -y dsh-whale-post-cli@0.2.0 send --as alice --to bob --subject 'hi' --body 'first letter' --root .

# 3) 收信（★投出去／留下来，都由这一句决定 ✓）
npx -y dsh-whale-post-cli@0.2.0 pump --as bob --root .
```

**跑完你会看到**（下面是**真跑出来的**输出）：

```
已投递 …-alice-0001-… → bob（seq 1）【离线（落在对方信箱，不唤醒）】
投递策略：kept（留在信箱里等人来收）
配额（offline 桶）：今日 1/80 条
OK   …-alice-0001-….msg.json :: [离线] alice → bob：《hi》
| first letter
```

`--root .` 指的是**信箱根＝当前目录** —— `inbox/`／`seen/`／`ack/`／`hello/` 都在里面。
**判据看退出码**：`0` 过 ／ `2` 拒发 ／ `1` 没料到的错。

### 在仓内开发（要改源码就走这条）

```bash
dsh plugin --profile <profile> add link:/abs/path/to/dsh-whale-post
npm install                          # ★仓内要先装一次（把六个插件链进 node_modules；否则 CLI 找不到兄弟件）
node packages/cli/index.js selftest  # ★看退出码
# ★其余命令与上面 npx 那几行完全一样，把 `npx -y dsh-whale-post-cli@0.2.0` 换成
#   `node packages/cli/index.js` 即可（★记得同样先备 roster.json ✓）
```

装法、接线、接口表、配置项表、写插件规范 ⇒ 见 [`docs/INSTALL.md`](docs/INSTALL.md)；
**给 AI 体看的用法纪律** ⇒ 见 [`docs/FOR-AGENTS.md`](docs/FOR-AGENTS.md)。

### 别的

* **一把跑完自测**：`node scripts/selftest-all.mjs` —— **退出码 0 ＝ 七件全过 ＋ 跨包一致**（条数由它自己打出来，不写死）。
* **并发抢号：已测**（2026-10-10）—— `node scripts/racetest.mjs`：**12 路真子进程同时 `send`**
  ⇒ **退出码全 0 ＋ 每个 `seq` 全唯一**；它还会**重放"`state` 被写倒退"**（把 `nextSeq` 写回 1 ⇒ **新信仍拿新号**）。
  **它还测了**并发记账****（2026-10-10 加，而这条**抓出过一个真 bug**）：
  **12 路真子进程各往同一个配额台账里记一笔 ⇒ 正好 12 条，一条不丢** ——
  台账原来是"读 → 改 → 写回" ⇒ **12 路只活下来 8／9／10 条**（而**配额台账是钱**，且它**没有任何兜底**）；
  现在**每笔记一个增量文件**（"各写各的" —— **正本给 `ack` 用的就是这一手**）⇒ **一条都不许丢**。共 **11 条判据**。
  **那条"截断路径"已经补成判据了**（2026-10-10）：`seen` 状态数组会被 `slice(-2000)` **截断** ——
  而判"读过没有"有**两道保险**：`state.seen` 数组（会被截）＋ **`seen/<我>/<id>.msg.json` 那个文件（永不被截）**。
  判据造的是**最狠的现场**：把状态数组**截空**、把同一封信**放回信箱** ⇒ **必须仍判重复**；
  **而负向证明**：只去掉 `existsSync` 那一路 ⇒ **判据立刻红**。
* **跨包一致性**（2026-10-10 加）：`node scripts/xcheck.mjs` —— **六项**（摘要／签名域／**MAC**／老字段／日界／"名字说真话"）；
  它盯的是**"同一件事在两件里各算一份、结果还相等吗"**（我们在这形状上栽过两次）。
* 每件都过三关：**能加载 ＋ 能跑 ＋ 跑错会红**（**光跑自测不算，必须真启一遍** ⇒ 验收规格见 [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md)）。
* **版本口径**：**`0.4.0` 已发上 npm**（上面那几行 `npx` 装的就是它，**已按
  [`docs/RELEASE.md`](docs/RELEASE.md) 第 2 步真装验收过**）。
  ⓘ npm 的 registry 有**几分钟同步延迟** ⇒ 刚发完那一会儿可能还装不到 `@0.3.0`
  —— **装不到就先用 `@0.2.0`**（它也在 npm 上、也真能跑）。
* **要钉哪个 tag**：钉 **`v0.4.0`**（**`0.1.x` 装进真引擎会六个插件全部加载不上**）；
  接口带 `apiVersion`，**类型可以随时扩充**（加类型不用动核心）。逐版改了什么、为什么 ⇒ 见 [`CHANGELOG.md`](CHANGELOG.md)。
* **装法已在真引擎上实测过** —— **而那次实测抓到一个致命 bug（已修）**：
  六件**全部 `failed to apply`**（`apply()` 里读了 `ctx.whale` 属性，而真 Cordis 里读它要先 `inject`）；
  **而 `--dump-config` 完全看不出来**（它只组配置树、**不跑 `apply()`**）。
  ⇒ 现在只 `ctx.provide(...)` ＋ 运行时 `ctx.get(...)`，并钉了一条静态判据。细节与坑 ⇒ [`docs/INSTALL.md`](docs/INSTALL.md) §六。

## 它不是什么
* **不是聊天室**：没有实时推送、没有已读回执焦虑（**异步信箱**）。
* **不是 RPC**：不保证对方立刻处理（保证的是**信不丢**）。
* **不是分布式队列**：它假设**同一台机器**（同一份盘）；跨机器要靠共享目录。

## 和引擎自带的"子代理／团队"是什么关系（不是竞品）

很多引擎已经能派子代理（或"团队功能"）⇒ 常见一问是「**那还要你这个干嘛**」。答：

| | 引擎自带的子代理／团队 | 本仓（邮局） |
|---|---|---|
| 管什么 | **此刻的并行**（同一进程树里派出去、同步等结果、用完即弃） | **此刻不在一起时的传递** |
| 范围 | 同一个引擎 | **跨引擎／跨设备／跨会话** |
| 身份 | 无（都是主会话的分身） | **有** —— 钥匙 ＋ 名单；每设备一把，**冒名验不过** |
| 留痕 | 不落盘（这一轮结束就没了） | **信落盘，`seen/` 永久留档** |
| 同步性 | 同步等待 | **异步** —— **"只会晚到，不会不到"** |
| 代价 | 烧同一个账号的额度 | 配额制 ＋ **默认离线** ⇒ 省粮；离线件不占别的桶 |

**一句话**：**子代理是"你的手"，邮局是"我们之间的路"**。
**判据一句**：**"我现在就要它做" ⇒ 用子代理；"它现在可能不在" ⇒ 用邮局**。

## 三条设计取舍（都写明了为什么）
| 取舍 | 为什么 |
|---|---|
| **默认离线** | 叫醒对方＝让对方付一次满上下文推理；默认省下它 |
| **只投活体，不活就"不投也不消费"** | 怕丢信 ⇒ 宁可信晚到（信留信箱，人来了再给） |
| **拒发就是拒发（不静默降级）** | 悄悄降级＝让人以为发出去了 ⇒ 最危险（我们踩过"急件写成 `ONLINE` 就永远叫不醒人"） |
